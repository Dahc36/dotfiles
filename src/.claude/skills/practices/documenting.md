# Documenting

Documentation should be easy to read both as a formatted .md and when reading the code.

## People don't want to read

Information should be distilled to only the essential, while still conveying the important information.
The shorter the better, without compromising understanding.

## Tables should be readable

Tables should have whitespaces to help code readability.
Tables should not be too wide, if they are, consider alternative options.

## Sequential instructions should be numbered steps

Numbered steps are easy to follow in order, add sub-steps for both multiple-step steps and sub-steps with NOTE: prefix for clarifications.

## Enumerations should each get their own line

When defining multiple processes, options or any list of items: use a list that gives each option its own line.
